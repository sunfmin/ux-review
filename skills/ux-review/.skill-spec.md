# ux-review — skill spec

- **name**: `ux-review`
- **description**: Design or review a screen or flow of a data-dense internal tool for usability, using rulings distilled from a survey of UX design philosophy (Norman, Nielsen, Tognazzini, GOV.UK, Magic Ink, WCAG). Source research: `payroll/docs/research/ux-design-philosophy.md`.
- **target**: dedicated repo `sunfmin/ux-review`
- **visibility**: public
- **needs**: none (single SKILL.md, no scripts)

## should_fire

1. "Do a UX review of the payslip list page in internal/web/payslip_pages.go"
2. "This employee form feels confusing to use. What's wrong with it?"
3. "Should the 'lock pay period' button have a confirmation dialog or an undo?"
4. "I'm about to build a new admin screen for approving expense claims — help me get the interaction design right before I write it"
5. "When should this form validate — on blur or on submit? And where do the errors go?"

## decoys

1. "Check this page for accessibility — contrast, focus rings, aria labels" → `web-design-guidelines`
2. "Design a bold landing page for our new product" → `frontend-design`
3. "Is this Go module too complex? Review the design" → `complexity-review`
4. "Add a `notes` column to the employees table migration" → none
5. "Write table-driven tests for the payslip handler" → `go-test-conventions`

## examples

- `/ux-review internal/web/payslip_pages.go`
- "UX review this diff before I open the PR"
- "Does deleting a draft need a confirm dialog?"

## functional_test

Input: `fixture/periods.html` in the skill-test fixture — a pay-period admin page with eight planted red flags
(hover-only action, state by color alone, cry-wolf confirm on Save, unreviewed money commit, empty error,
fixed-width button, strict input, dead-end empty state) and two Too-far traps (the form validates on submit,
not blur; the list is dense).

Success: the review reports at least 6 of the 8 planted flags in the `[flag] path:line — … / cost: / fix:` format,
ends with a one-line verdict, and does not recommend blur validation, a less dense table, or more confirmation dialogs.
